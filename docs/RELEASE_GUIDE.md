# Release Guide

## Purpose
A release marks a project version that is ready for users.

## Before a Release
- Review the changes included in the release.
- Check that documentation is up to date.
- Verify that relevant tests pass.
- Review known issues and limitations.
- Update the changelog when appropriate.

## Preparing the Release
1. Choose a version number according to VERSIONING.md.
2. Summarize the important changes.
3. Document breaking changes and migration steps.
4. Review the release notes for accuracy.

## Publishing
- Create a Git tag for the release when appropriate.
- Publish release notes with the version.
- Use the project's established release process.
- Do not claim that a release is published until it is available.

## After the Release
- Check that release links and notes are accessible.
- Track reported problems.
- Prepare follow-up fixes when needed.

## Release Checklist
- [ ] Changes reviewed
- [ ] Tests checked
- [ ] Documentation updated
- [ ] Version verified
- [ ] Release notes reviewed

## Important Note
This guide describes a general process. Adapt it to the project's actual build, test, and release setup.
