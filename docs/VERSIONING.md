# Versioning Guide

## Purpose
Versioning helps users understand the scope of each project release.

## Semantic Versioning
When the project uses semantic versions, follow the format MAJOR.MINOR.PATCH.

- MAJOR: incompatible changes.
- MINOR: new functionality that remains compatible.
- PATCH: backward-compatible fixes.

## Release Notes
For each release:
- Summarize important changes.
- Mention fixes and new features.
- Highlight breaking changes.
- Include migration notes when necessary.

## Tags
Use Git tags to identify release points in the repository.

## Best Practices
- Keep version numbers consistent.
- Update the changelog when preparing a release.
- Do not publish a release before checking its contents.
- Explain breaking changes clearly.

## Important Note
Adopt a versioning scheme that matches the project's actual release process. Do not assign release numbers to changes that have not been published as releases.
