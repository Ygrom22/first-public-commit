# Commit Guidelines

## Purpose
Clear commit messages make project history easier to understand.

## Message Format
Use a short, descriptive message that explains the change.

A common format is:
type: short description

## Common Types
- docs: documentation changes.
- feat: a new feature.
- fix: a bug fix.
- refactor: code restructuring without changing behavior.
- test: adding or updating tests.
- chore: maintenance tasks.

## Good Examples
- docs: add installation guide
- fix: correct configuration example
- feat: add input validation
- test: cover empty input

## Best Practices
- Use the imperative mood when practical.
- Keep the subject concise.
- Describe the actual change.
- Avoid vague messages such as "updates" or "changes".
- Keep unrelated changes in separate commits.

Clear commit messages help everyone review and maintain the project.
