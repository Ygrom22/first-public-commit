# Documentation Style Guide

## Purpose
Keep project documentation clear, consistent, and easy to maintain.

## Writing Guidelines
- Use clear and simple language.
- Prefer short paragraphs.
- Use descriptive headings.
- Explain technical terms when needed.
- Avoid unnecessary repetition.

## Markdown Formatting
- Use headings in a logical order.
- Use bullet lists for related items.
- Use code formatting for file names and commands.
- Use links when they provide useful context.

## File Naming
- Use descriptive file names.
- Prefer uppercase words separated by underscores for documentation file names.
- Place general guides in the docs/ directory.

## Maintenance
- Review documentation when project information changes.
- Keep links accurate.
- Correct spelling and formatting issues.

Consistency makes documentation easier for everyone to use.
